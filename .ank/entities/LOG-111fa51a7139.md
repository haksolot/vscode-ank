It now publishes the one vsix it built to the Marketplace and to Open VSX, in that order and after the GitHub release exists, so an expired token costs a re-run of a publish step rather than the whole build. Publishing the same file to both registries rather than repackaging per registry is what makes the bytes a Cursor user installs the bytes that were tested here. It also installs ank, because the release job runs the same unit suite CI does and that suite locates the real binary. Open VSX was chosen alongside the Marketplace because ank's audience skews toward agent tooling and a good share of them are on a fork that cannot reach the Marketplace at all. Two things stay human: the namespace claim on Open VSX, which is a one-time act that fails on a namespace that exists, and the tokens themselves. docs/releasing.md carries both. The lockfile hazard from earlier today is now a script and a line in AGENTS.md, since any npm install run behind the mirror reintroduces it.
